# 云主机单端口部署与公网访问检查

> 日期: 2026-07-03
> 目标: 说明 `127.0.0.1` 安全默认值与云主机公网访问的配置差异。

## 1. 结论

本项目默认绑定 `127.0.0.1:12345`，因为同一端口同时承载代理 API 和可读写上游密钥的 `/admin`。应用只提供 HTTP，**禁止把应用端口直接暴露到公网**。

公网部署必须同时满足：

1. 使用 Nginx、Caddy、云负载均衡等 TLS 反向代理，只对外开放 HTTPS。
2. 应用端口仅绑定 loopback 或受防火墙保护的私网地址。
3. 同时设置强随机 `PROXY_API_KEY` 和 `ADMIN_API_KEY`，且两个值不同。
4. 远程客户端只使用 HTTPS 地址，不使用 `http://<公网IP>:12345`。

公网访问地址形态应为：

```text
https://ai-proxy.example.com/admin
https://ai-proxy.example.com/v1
```

## 2. 二进制直接运行

`.env` 示例：

```dotenv
PORT=12345
HOST=127.0.0.1
PROXY_API_KEY=请生成至少32字节的强随机代理密钥
ADMIN_API_KEY=请生成另一个至少32字节的强随机管理密钥
VS_AI_PROXY_AUTO_UPDATE=0
```

同机 TLS 反向代理转发到 `http://127.0.0.1:12345`。公网安全组不得放行 12345，只放行反向代理的 443。

启动后日志中应看到后端仍为 loopback：

```text
监听地址=http://127.0.0.1:12345
```

## 3. Docker Compose 运行

`.env` 示例：

```dotenv
PORT=12345
BIND_HOST=127.0.0.1
PROXY_API_KEY=请生成至少32字节的强随机代理密钥
ADMIN_API_KEY=请生成另一个至少32字节的强随机管理密钥
```

说明：

- 容器内部使用 `HOST=0.0.0.0`，宿主机发布地址仍必须保持 `BIND_HOST=127.0.0.1`。
- Compose 会让容器监听端口、target port 和 published port 始终跟随同一个 `PORT`。
- Compose 显式设置 `VS_AI_PROXY_AUTO_UPDATE=0`；容器升级应通过构建和替换镜像完成。
- TLS 反向代理转发到宿主机 `127.0.0.1:12345`。
- 不得使用 `BIND_HOST=0.0.0.0` 把明文 HTTP 后端直接发布到公网。

## 4. 云安全组/防火墙

公网访问还需要同时满足：

1. 云厂商安全组只对公网放行 TCP `443`，不放行应用端口 `12345`。
2. TLS 证书有效，HTTP 必须跳转到 HTTPS，不能回退到裸 HTTP 后端。
3. `PROXY_API_KEY` 和 `ADMIN_API_KEY` 均为强随机值且互不相同。
4. Docker 模式下 `docker compose config` 应显示 `host_ip: 127.0.0.1`。
5. 如反向代理不在同一主机，只能通过受防火墙和访问控制保护的私网连接后端。

## 5. 验证命令

服务器内执行：

```bash
curl -i http://127.0.0.1:12345/admin
curl -i http://127.0.0.1:12345/admin/api/config
curl -i -H "Authorization: Bearer $ADMIN_API_KEY" http://127.0.0.1:12345/admin/api/config
curl -i http://127.0.0.1:12345/v1/models
curl -i -H "Authorization: Bearer $PROXY_API_KEY" http://127.0.0.1:12345/v1/models
```

预期：

- 未登录的 `/admin` 返回 `401` 和登录页 HTML。
- 未带 token 的 `/admin/api/config` 在设置 `ADMIN_API_KEY` 后返回 `401`。
- 带 Bearer token 的 `/admin/api/config` 返回 `200`。
- 未带 token 的 `/v1/models` 在设置 `PROXY_API_KEY` 后返回 `401`。
- 带代理 Bearer token 的 `/v1/models` 返回 `200`。

远程机器执行：

```bash
curl -i https://ai-proxy.example.com/admin
curl -i -H "Authorization: Bearer $PROXY_API_KEY" https://ai-proxy.example.com/v1/models
```

远程验证必须确认 TLS 证书有效、裸 HTTP 不可访问、两个未授权请求均返回 `401`。如果只能通过 `http://<公网IP>:12345` 访问，部署不满足上线条件。
