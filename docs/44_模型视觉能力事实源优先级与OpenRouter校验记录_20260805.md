# 模型视觉能力事实源优先级与OpenRouter校验记录

这次问题不是 OpenRouter 误报。OpenRouter 当前对 `minimax/minimax-m3` 仍然声明 `text+image+video->text`，但本地 `model-selection/*.json` 里若写了 `supports_vision:false`，它会覆盖更上层的事实源，最后在 Visual Studio / Copilot 里表现成“模型不支持图像引用”。

## 优先级

1. 用户保存的 `config.json` 里的 `models[]`
2. 本地 `internal/provider/model-selection/*.json`
3. 内置 `internal/provider/model-metadata/models.json`
4. 远程 OpenRouter / LiteLLM 补充元数据

要点：
- 远程元数据是异步补充，不是实时主真相。
- `EnrichMetadata` 只补缺，不覆盖已存在的本地条目。
- 因此，selection 里的错误布尔值会压过远程正确值。

## 这次没有改的 false

其余 `supports_vision:false` 不能直接当错。它们里很多是纯文本模型，或者当前没有足够证据证明视觉支持。以后排查时，不要把“未命中元数据”自动等价成“支持视觉”。

## 诊断顺序

发现某个模型在 VS / Copilot 里被判定为“不支持图像引用”时，按这个顺序查：

1. 先看 `config.json` 的 `models[]`
2. 再看对应 provider 的 `model-selection/*.json`
3. 再看内置 `model-metadata/models.json`
4. 最后才看 OpenRouter / LiteLLM 的远程补充

如果前面任一层显式写了 `false`，就不要假设远程补充能自动纠正。
